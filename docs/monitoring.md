# Monitoring and Observability

## Overview

The Online Boutique Kubernetes environment uses the Prometheus and Grafana monitoring stack.

The monitoring architecture is:

```text
                    Kubernetes
                        |
          +-------------+-------------+
          |                           |
          v                           v
  kube-state-metrics            node-exporter
          |                           |
          +-------------+-------------+
                        |
                        v
                   Prometheus
                        |
                        v
                     Grafana
                        |
                        v
                  Dashboard



Monitoring Components
Prometheus

Prometheus collects and stores time-series metrics from Kubernetes monitoring targets.

It is responsible for:

Scraping metrics
Storing time-series data
Providing the PromQL query language
Evaluating monitoring rules
Grafana

Grafana provides visualization of Prometheus metrics.

It is used for:

Dashboards
Time-series visualization
Application and infrastructure monitoring
Exploring Prometheus metrics
kube-state-metrics

kube-state-metrics exposes metrics about Kubernetes objects.

Examples include:

Pods
Deployments
ReplicaSets
Services
Nodes
Namespaces

This allows Prometheus to query Kubernetes state.

node-exporter

node-exporter exposes Linux/node-level metrics such as:

CPU
Memory
Filesystem
Network
Disk-related metrics
Alertmanager

Alertmanager handles alerts generated by Prometheus.

It is responsible for:

Receiving alerts
Grouping alerts
Routing alerts
Sending notifications
Installation

The monitoring stack was installed using the Prometheus Community Helm repository.

Add the Helm repository
helm repo add prometheus-community \
  https://prometheus-community.github.io/helm-charts

Update the repository:

helm repo update
Create the monitoring namespace
kubectl create namespace monitoring
Install kube-prometheus-stack
helm install monitoring \
  prometheus-community/kube-prometheus-stack \
  --namespace monitoring

The Helm release name is:

monitoring

The Kubernetes namespace is:

monitoring
Verify the installation
kubectl get pods -n monitoring

Services:

kubectl get svc -n monitoring

Helm release:

helm list -n monitoring
Accessing Prometheus

For local Minikube access:

kubectl port-forward -n monitoring \
  svc/monitoring-kube-prometheus-prometheus 9090:9090

Prometheus is then available at:

http://localhost:9090

The port-forward is only for local browser access.

Grafana communicates with Prometheus using the Kubernetes Service DNS name.

Accessing Grafana

For local access:

kubectl port-forward -n monitoring \
  svc/monitoring-grafana 3000:80

Grafana is then available at:

http://localhost:3000
Grafana credentials

The Grafana administrator password can be retrieved with:

kubectl get secret monitoring-grafana \
  -n monitoring \
  -o jsonpath="{.data.admin-password}" | base64 -d
echo

Username:

admin
Grafana Prometheus Datasource

The Prometheus datasource is configured automatically by
kube-prometheus-stack.

The datasource uses the Kubernetes Service:

http://monitoring-kube-prometheus-prometheus.monitoring:9090/

This is different from the local browser address:

http://localhost:9090

localhost:9090 is only the local port-forward.

Grafana communicates with Prometheus internally through Kubernetes DNS.

PromQL Verification
Target health
up

The up metric indicates whether Prometheus successfully scraped a target.

Values:

1 = scrape successful
0 = scrape failed
Kubernetes pod information
kube_pod_info

This verifies that Kubernetes object metrics are available through
kube-state-metrics.

Running pods
sum(kube_pod_status_phase{
  namespace="default",
  phase="Running"
})

This counts pods in the Running phase in the default namespace.

Pod restarts
sum by (pod) (
  increase(
    kube_pod_container_status_restarts_total{
      namespace="default"
    }[15m]
  )
)

This shows container restart activity per pod during the previous
15 minutes.

The restart metric is a cumulative counter. increase() is used to
calculate how much the counter increased during the selected time
window.

Troubleshooting
Prometheus pod is not ready

Check:

kubectl get pods -n monitoring

Then:

kubectl describe pod <prometheus-pod> -n monitoring

Check logs:

kubectl logs <prometheus-pod> -n monitoring
Grafana cannot query Prometheus

Verify the Prometheus service:

kubectl get svc -n monitoring

Verify the Grafana datasource uses:

monitoring-kube-prometheus-prometheus.monitoring:9090

Test Prometheus directly:

kubectl port-forward -n monitoring \
  svc/monitoring-kube-prometheus-prometheus 9090:9090

Then open:

http://localhost:9090
Grafana is unavailable

Check:

kubectl get pods -n monitoring

Check:

kubectl get svc monitoring-grafana -n monitoring

Then create the port-forward again:

kubectl port-forward -n monitoring \
  svc/monitoring-grafana 3000:80
